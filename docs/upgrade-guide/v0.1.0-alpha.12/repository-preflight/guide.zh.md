# 升级 alpha.12 → alpha.13：仓库预检

[English](guide.md) | 中文

## 变更

执行和交付请求在提供卡片前运行有界只读仓库预检。阻塞观察发布诊断，不授予许可。卡片绑定规范仓库、HEAD 和候选 tree；确认与执行时再次检查。新插件私有工作流记录使用 v8；storage-domain 和 journal 外壳仍为版本 1。这不是核心 Session 格式变更，也不构成核心持久化清单 acknowledgement。[持久化说明](../../../persistence.zh.md)标明变更类型及读取规则。既有 v1–v7 读取器保持冻结，记录保持可读且不重写；缺少预检证明的旧请求或授权必须重新请求操作并由用户决定。

## 迁移

1. 替换插件前结束或取消活动工作并停止全部写入者。保留两份权威存储及当前包和配置，以便恢复。
2. 通过现有源码宿主兼容的包布局安装已验证候选。不编辑 journal、不重置已消耗预算、不重放旧 Authorize 序号。
3. 查看操作预检状态。解决准确的不兼容项后再请求新卡片。常规独立仓库可启用 `extensions.worktreeConfig`；`.git/config` 或 `.git/config.worktree` 中的危险键仍拒绝执行。链接工作树与嵌套仓库仍不支持。
4. 核对新卡片上的仓库和 HEAD/tree，然后作出决定。Approve 与 Authorize 仍然独立；新的用户输入可能使回执失效。
5. generatedPaths 只填写可丢弃产物的字面路径。新 brief 拒绝 glob 和排除整个仓库。修订并重新批准受影响的 brief，不重写历史输入。

Git 超时诊断区分不同进程结果。配置提供普通命令、完整性检查与总预检预算。不根据耗时推断损坏，不自动修改 Git 配置、运行清理或绕过检查。

Alpha.12 拒绝 v8 记录。写入 v8 后，停止依赖操作并保留更新的 Session／工作流存储。回退使用兼容读取器或隔离且匹配的升级前备份，不得用旧备份覆盖更新的存储。仅回退代码不能证明数据兼容。
